# xlsx 数据类型能力边界

本文说明**目前支持哪些数据类型、每个类型在「导入 → 存储 → 显示 → 导出」四个阶段的实际行为，以及明确的边界**。

对应实现：

| 阶段 | 位置 |
| --- | --- |
| 导入（ExcelJS → 快照） | `backend/src/features/documents/formats/xlsx/xlsx.ts` → `readXlsx()` |
| 存储 | 服务端 Y.Doc（扁平 key），物化为 `SnapshotWorkbook` |
| 显示 | `frontend/src/app/spreadsheet/engine/model/worksheet.ts` → `cellText()` + `value-format.ts` |
| 导出（快照 → ExcelJS） | `backend/src/features/documents/formats/xlsx/xlsx.ts` → `writeXlsx()` |

入口由 [`formats/index.ts`](../index.ts) 按扩展名分发（`.xlsx / .xlsm`），导入接口
`POST /api/v1/documents/import`，导出接口 `GET /api/v1/documents/:id/export.xlsx`。

> 快照里的 `t` 是值类型：`1=STRING`、`2=NUMBER`、`3=BOOLEAN`、`4=FORCE_STRING`。

---

## 1. 单元格值类型

| Excel 里的类型 | 导入后的存储 | 显示 | 导出 | 边界 |
| --- | --- | --- | --- | --- |
| **文本** | `v: string`，`t:1`；单元格格式为 `@` 时 `t:4`（强制字符串） | 原样文本 | 文本 | — |
| **数字** | `v: number`，`t:2`；格式串存样式 `n.pattern` | 有数字格式时按格式渲染，否则 `String(v)` | 数字 + `numFmt` | 见 §2 数字格式 |
| **布尔** | `v: boolean`，`t:3` | `TRUE` / `FALSE` | 布尔 | — |
| **日期 / 时间** | `v:` **Excel 序列号（数字）**，`t:2`，格式串存 `n.pattern` | 按 `n.pattern` 用 **UTC** 组件渲染 | 数字 + 日期 `numFmt` | 1904 日期系统不保留；无格式的日期补默认 `yyyy-mm-dd`（有时间则带 `hh:mm:ss`） |
| **公式** | `f: "=..."`（带 `=`）+ `v:` 缓存结果，`t` 跟结果类型 | **显示公式原文，不计算结果**（与 Excel 编辑栏一致） | `{ formula, result }` | 引擎不求值；无缓存结果时 `v=""`、`t:1`；共享公式按格翻译，导出拆成独立公式（不保留共享组） |
| **错误值**（`#N/A` 等） | `v:` 错误文本，`t:1` | 文本 | **文本**（不再是 Excel 错误） | 丢失「错误」语义 |
| **富文本** | 压平成纯字符串，`t:1` | 纯文本 | 文本 | 段内字体/颜色/字号丢失；`p` 字段未使用 |
| **超链接** | 只存显示文本，`t:1` | 文本 | 文本 | URL / tooltip 丢失（快照无链接字段） |
| **空单元格** | 跳过 | 空 | 空 | 只有样式、没有值的单元格不会导入（ExcelJS 将其视为 Null 类型） |
| **合并区从属格** | 不写入值，只保留左上角 | — | 由 `mergeData` 还原合并 | 导入时避免把主格值复制到合并区每一格 |

### 1.1 日期为什么存序列号

存「序列号 + 格式串」而不是格式化后的文本：

- 导出时仍是数字，不会永久退化成字符串；
- 显示由前端按 `n.pattern` 渲染，和 Excel 的行为一致；
- 代价是显示层必须实现 §2 的格式渲染（已实现）。

### 1.2 公式与共享公式

- 读取公式时使用 ExcelJS 的 `cell.formula` getter：它会把**共享公式的从属格翻译成当前格自己的公式**。
- 如果直接读 `cell.value.sharedFormula`，拿到的是主格地址（例如 `B1`），会被错误地存成 `=B1`。
- 导出时每个公式格都写成独立公式，**不重建**共享公式的主从关系。

## 2. 数字格式（显示层）

服务端只负责把 `numFmt` 原样存进 `n.pattern`；渲染发生在前端 `value-format.ts`。

### 支持

| 类别 | 支持的形式 |
| --- | --- |
| 整数 / 小数 | `0`、`0.00`、`#`、`?`、`000`（不足补零） |
| 千分位 | `#,##0`、`#,##0.00` |
| 百分比 | `0%`、`0.00%`（自动 ×100 并加 `%`） |
| 日期 | `yyyy`、`yy`、`m`、`mm`、`d`、`dd` |
| 时间 | `h`、`hh`、`s`、`ss`、`AM/PM`、`A/P`（`mm` 紧邻小时或 `ss` 时按分钟处理） |
| 字面量 | 引号内容（`"年"`）、反斜杠转义；`[...]` 内的颜色/条件代码会被跳过 |

### 不支持 / 降级

| 形式 | 实际表现 |
| --- | --- |
| 货币符号等数字格式里的字面量（`$#,##0.00`、`¥#,##0`） | **符号被丢弃**，只渲染数字部分（`1,234.57`） |
| 科学计数（`0.00E+00`） | 按普通小数渲染，结果不正确 |
| 多段格式（`正;负;零;文本`） | 只取第一段；负数在第一段结果前加 `-` |
| 条件/颜色代码 `[Red]`、`[<=100]` | 跳过，不参与渲染 |
| 会计格式、`_` 占位、`*` 填充 | 不支持 |

> 这些只影响**显示**；原始 `numFmt` 字符串始终保留在 `n.pattern` 里，导出时会写回。
> 未命中任何格式分支时，显示层回退到 `String(value)`。

## 3. 样式

| 样式 | 读 | 写 | 说明 |
| --- | :---: | :---: | --- |
| 字体名 / 字号 | ✅ | ✅ | `ff` / `fs`（磅） |
| 粗体 / 斜体 | ✅ | ✅ | `bl` / `it` |
| 下划线 / 删除线 | ✅ | ✅ | `ul` / `st`，**只区分有/无，不区分单双线** |
| 字体色 / 背景色 | ✅ | ✅ | `cl` / `bg`，统一成小写 `#rrggbb` |
| 水平 / 垂直对齐 | ✅ | ✅ | `ht` / `vt`；`justify`/`distributed` 映射到最接近的档位 |
| 自动换行 | ✅ | ✅ | `tb = WRAP` |
| 边框（四边 + 对角线） | ✅ | ✅ | `bd.t/r/b/l/tl_br/bl_tr` |
| 行/列级样式 | ✅ | ✅ | `rowData.s` / `columnData.s`；引擎按「单元格 > 行 > 列」继承（只取一层，不深合并） |
| 数字格式 | ✅ | ✅ | `n.pattern` |

**不映射**：主题色（无 `argb` 的 `{theme, tint}` 直接跳过）、渐变填充、单元格保护、缩进、文本旋转、`shrinkToFit`。

## 4. 工作表结构

| 属性 | 读 | 写 | 显示 | 边界 |
| --- | :---: | :---: | :---: | --- |
| sheet 名 / 顺序 | ✅ | ✅ | ✅ | — |
| sheet 隐藏 | ✅ | ✅ | ✅ | 全部隐藏时导入会把第一张显示出来 |
| tabColor | ✅ | ✅ | ✅ | — |
| 合并单元格 | ✅ | ✅ | ❌ | **引擎只存不渲染** |
| 行高 / 列宽 | ✅ | ✅ | ✅ | 单位换算有舍入：列 `px = width*7+5`，行 `px = pt*96/72` |
| 行/列隐藏 | ✅ | ✅ | ✅ | 空行的隐藏 ExcelJS 自己不保留 |
| 默认行高 / 列宽 | ✅ | ✅ | ✅ | — |
| 网格线显隐 | ✅ | ✅ | ✅ | — |
| 网格线颜色 | ❌ | ❌ | — | 导入恒为 `null` |
| 冻结窗格 | ✅ | ✅ | ❌ | **引擎只存不渲染** |
| 缩放 | ❌ | ❌ | — | 导入恒为 `1`，导出不写 |

## 5. 明确不支持的内容

以下内容目前**不解析、不保留**（导入时丢弃，导出时不会出现）：

- 图表、图片、形状
- 条件格式、数据验证、下拉列表
- 批注、批注作者
- 超链接地址（只保留显示文本）
- 数据透视表、切片器
- 命名区域、Excel 表格（ListObject）
- 打印设置、页眉页脚、页面布局
- VBA / 宏（`.xlsm` 的宏会被丢弃；导出恒为 `.xlsx`）
- 外部链接、公式引用关系
- 1904 日期系统设置
- `.xls`（旧 BIFF 格式）—— **不支持，只承诺 `.xlsx / .xlsm`**

## 6. 体量约束

| 约束 | 值 | 位置 |
| --- | --- | --- |
| 单次上传大小 | 20 MB | `documents.controller.ts` 的 `MAX_XLSX_BYTES` |
| 单元格总数 | 2,000,000 | `document.service.ts` 的 `MAX_IMPORT_CELLS`，超限返回 413 |
| 解析线程 | 当前请求线程（同步） | 更大体量应改为异步队列 + 任务状态查询 |

## 7. 导入降级提示（warnings）

`readXlsx` 返回 `{ workbook, warnings, cellCount }`。以下情况会记入 `warnings`，
当前由 `document.service.ts` 写日志，**不返回给客户端**：

| 提示 | 触发条件 |
| --- | --- |
| 富文本已压平为纯文本 | 单元格值包含 `richText` |
| 超链接已降级为纯文本 | 单元格值包含 `text`（超链接对象） |
| 未识别的单元格值类型，已跳过：`…` | 值对象不属于公式 / 错误 / 富文本 / 超链接 |
| 全部工作表都是隐藏状态，已显示第一张 | 所有 sheet 的 `hidden` 都是 1 |

## 8. 显示层要点（前端）

`Worksheet.cellText(cell, style)` 的优先级：

1. 有公式 `f` → 显示公式原文；
2. 空值 → 空串；
3. 布尔 → `TRUE` / `FALSE`；
4. 数字且有 `n.pattern` → 按格式渲染；
5. 其它 → `String(v)`。

注意：

- 显示数字格式只作用于**数字**（日期在快照里也是数字），字符串不会套格式。
- 公式格显示的是**公式文本**，不是结果——和 Excel 的编辑栏一致；单元格画布上展示的是 `cellText` 的结果。
- 合并、冻结在模型里保存完整，但渲染层尚未实现。
