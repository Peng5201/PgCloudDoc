# xlsx 读写（服务端）

Excel 文件 ↔ 协同快照（`SnapshotWorkbook`）的映射。

- **导入**：`POST /api/v1/documents/import` → `readXlsx` → `applySnapshot` 写入 Y.Doc → 归档
- **导出**：`GET /api/v1/documents/:id/export.xlsx` → `materialize` 读 Y.Doc → `writeXlsx`

## 为什么在服务端

1. 协同真源是服务端 Y.Doc，导出必须基于它；前端手里的数据可能落后于别人的编辑
2. ExcelJS 不打进浏览器包（省掉一个 ~1MB 的懒加载 chunk）
3. 导入是「数据摄取」流程，天然属于服务端：解析 → 写 Y.Doc → 落库

## 覆盖范围（P0 + P1 + 低成本 P2）

| 能力 | 读 | 写 |
| --- | :---: | :---: |
| 文本 / 数字 / 布尔 | ✅ | ✅ |
| 公式 + 缓存值 | ✅ | ✅ |
| 日期（序列号 + `n.pattern`） | ✅ | ✅ |
| 数字格式（千分位/百分比/小数位） | ✅ | ✅ |
| 合并单元格 | ✅ | ✅（引擎只存不渲染） |
| 行高 / 列宽 | ✅ | ✅ |
| 字体 / 填充 / 对齐 / 换行 / 边框 | ✅ | ✅ |
| 行列隐藏、默认宽高、网格线 | ✅ | ✅ |
| sheet 名 / 顺序 / 隐藏 / tabColor | ✅ | ✅ |
| 冻结窗格 | ✅ | ✅（只存不渲染） |

> 逐类型的能力边界（含显示层与降级行为）见 **[DATA-TYPES.md](DATA-TYPES.md)**。

## 已知限制

| 项 | 现状 |
| --- | --- |
| 富文本 | 压平成纯文本（快照 `p` 只占位） |
| 超链接 | 只保留显示文本 |
| 主题色 / 渐变填充 | 不解析（宁可默认色也不写错色） |
| 条件格式 / 数据验证 / 批注 / 图片 / 图表 / 命名区域 | 不解析（可后续塞进 `resources`） |
| 共享公式 | 读取时按格翻译成各自的公式；导出拆成独立公式，不保留共享组 |
| 缩放 | 不保留（导入恒为 1，导出不写） |
| `.xls`（BIFF） | **不支持**，只承诺 `.xlsx / .xlsm` |

## 限制与防护

- 上传大小：`FileInterceptor` 限制 20MB（`documents.controller.ts`）
- 单元格总数：`MAX_IMPORT_CELLS = 2_000_000`，超限返回 413
- 解析在当前请求线程里做；若将来出现更大的文件，应改为异步队列 + 任务状态查询

## 设计要点

- **日期存序列号 + 格式串**：导出时仍是数字，不会退化成字符串；显示由前端 `cellText` 按 `n.pattern` 渲染
- **样式去重**：`StyleRegistry` 按内容指纹合并进共享样式表
- **稀疏遍历**：导出只遍历实际单元格，不按 `rowCount × columnCount` 铺满
